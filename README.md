# Фільтр доставки для OkayCMS

У списку замовлень адмінки з'являється один select «Статус доставки», де статуси кожного
перевізника зібрані в окрему групу: «НП · Прибула», «УП · У відділенні» тощо. Поле пошуку
знаходить замовлення за номером відправлення будь-якого перевізника: ТТН Нової Пошти,
штрихкодом Укрпошти, номером Meest. Підказка в полі: «№, ім'я, телефон, ТТН…».

Статуси дають модулі доставки, підключені до фільтра:
[Нова Пошта](https://github.com/devSviat/NovaPoshta-OkayCMS),
[Укрпошта](https://github.com/devSviat/Ukrposhta-OkayCMS), Meest. Без жодного з них select не
з'являється, а пошук працює як у звичайній OkayCMS.

## Що потрібно

- PHP 8.5. Працює на чистій OkayCMS 4.5.3 і на [форку](https://github.com/devSviat/OkayCMS-Fork).
  Ядро не змінюється.
- Хоча б один модуль доставки, який підтримує цей фільтр. Версії перелічено нижче.

## Встановлення

1. Скачайте архів з [останнього релізу](https://github.com/devSviat/DeliveryFilter-OkayCMS/releases/latest)
   і розпакуйте його в `Okay/Modules/`, щоб з'явився каталог `Okay/Modules/Sviat/DeliveryFilter`.
2. Модулі → Мої модулі: встановіть і увімкніть Delivery Filter. Таблиць і налаштувань модуль не
   має.

Вимкнути чи видалити його можна будь-коли. Нова Пошта тоді повертає свій окремий select статусів
і пошук ТТН, Укрпошта лишається без фільтра.

## Як це виглядає

- Select стоїть між «Усі статуси» і «Усі мітки». Коли підключено один перевізник, групи без
  заголовка; коли кілька, кожна група стоїть під назвою перевізника. Усередині select'а є пошук.
- Вибирається один статус. Статус замовлення, мітка, дати й пагінація його не скидають, лічильники
  статусів угорі сторінки рахують ті самі замовлення.
- Номер відправлення знаходить замовлення, якщо він уже є в базі модуля доставки. Інший текст
  (ім'я, телефон, номер замовлення) шукає ядро.
- Старі закладки Нової Пошти (`?np_waybill=arrived`) відкриваються з переходом на нову адресу
  (`?delivery_status=np:arrived`).

## Сумісні модулі доставки

| Модуль | Версія | Ключ | Без цього модуля |
| --- | --- | --- | --- |
| Нова Пошта | 1.2.0 і новіші | `np` | свій select статусів і пошук ТТН, як раніше |
| Укрпошта | 1.2.0 і новіші | `up` | фільтра статусів і пошуку штрихкодом немає |
| Meest | у розробці | `meest` | фільтра статусів і пошуку немає |

Старіші версії модулів про фільтр не знають: Нова Пошта до 1.2.0 показує свій select статусів, як
і раніше, а Укрпошта до 1.2.0 фільтра статусів не має.

## Для розробників модулів доставки

Модуль доставки додає три ланцюгові розширення на
`Okay\Modules\Sviat\DeliveryFilter\Helpers\DeliveryFilterHelper`:

| Метод | Що робить ланка | Аргументи ланки |
| --- | --- | --- |
| `findDeliveryStatusFilters()` | дописує свою групу | `($filters)` |
| `filterByDeliveryStatus(array $filter, string $carrier, string $status)` | лише для свого ключа додає свій фільтр сутності замовлень | `($result, $filter, $carrier, $status)` |
| `findOrderIdsByShipmentNumber(string $keyword)` | впізнає свій формат номера й дописує id замовлень | `($ids, $keyword)` |

Група:

```php
$filters['np'] = [
    'title' => 'Нова Пошта',        // заголовок групи
    'short' => 'НП',                // префікс опції: «НП · Прибула»
    'options' => ['arrived' => 'Прибула', 'none' => 'Без накладної'],
    'legacy_param' => 'np_waybill', // необов'язково: старий GET-параметр, з якого буде редирект
];
```

Правила:

- Ключ перевізника має вигляд `[a-z][a-z0-9_]{0,15}`, статус `[a-z0-9_]{1,32}`. GET-параметр
  `delivery_status=<ключ>:<статус>` приймається лише з парою, яку описала якась група. Статус
  із самих цифр (`'123'`) PHP робить цілим ключем масиву; фільтр приймає й такий.
- Тексти беріть лише з мовних файлів модуля. Групу з символами поза
  `[\p{L}\p{N} .,'’()·/-]{1,64}` фільтр не показує. bootstrap-select 1.11.2 вставляє заголовок
  групи як HTML уже після того, як браузер декодував атрибут, тож одинарне `|escape` його не рятує.
  Шаблон фільтра тримає подвійне `|escape|escape`, а білий список символів стоїть другою лінією.
- Звуження `id`, лічильники статусів і текст у полі пошуку бере на себе фільтр. Якщо номер
  впізнали кілька перевізників, знайдені id об'єднуються.

Реєструйте ланки лише тоді, коли клас і всі три методи існують. Реєстрація розширення на метод,
якого немає, кидає виняток в `init()`, а `init()` модулів виконується на кожному запиті. Без цієї
перевірки модуль доставки без фільтра чи поруч зі старішою версією фільтра поклав би весь сайт:

```php
public function init()
{
    $helper = 'Okay\\Modules\\Sviat\\DeliveryFilter\\Helpers\\DeliveryFilterHelper';
    $hooks = [
        'findDeliveryStatusFilters' => 'deliveryStatusFilters',
        'filterByDeliveryStatus' => 'filterByDeliveryStatus',
        'findOrderIdsByShipmentNumber' => 'ordersByShipmentNumber',
    ];
    if (class_exists($helper) && array_all(array_keys($hooks), fn(string $m): bool => method_exists($helper, $m))) {
        foreach ($hooks as $method => $extension) {
            $this->registerChainExtension([$helper, $method], [DeliveryFilterExtender::class, $extension]);
        }
    }
}
```

Адмінка OkayCMS викликає `init()` і вимкнених модулів. Звідси два правила:

- Ланки фільтра зареєстровані й тоді, коли фільтр вимкнено; він тоді нічого не робить. Модуль, що
  тримає старий фільтр як запасний варіант, вибирає його за `class_exists(...)` і
  `Modules::isActiveModule('Sviat', 'DeliveryFilter')`.
- Ланки вимкненого модуля доставки теж зареєстровані. Кожна ланка мусить перевірити
  `Modules::isActiveModule()` свого модуля й повернути результат без змін, інакше група
  вимкненого перевізника з'явиться в select'і, а пошук знаходитиме його номери.
